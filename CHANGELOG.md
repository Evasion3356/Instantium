# Changelog

## 0.1.0 — Initial scaffold

- **Hub/Psykhanium caching** (`preload/hub.lua`) — ported from InstantHub's package-retention approach: Mourningstar and Psykhanium level/theme/UI/HUD/game-mode/breed resources stay resident across mission transitions via an independently-held `Managers.package` reference. Three checkboxes: Mourningstar Caching, Preload Hub at Character Select, Preload Psykhanium / Meat Grinder.
- **Memory tier system** (`core/memory_probe.lua`) — reads Darktide's native graphics-memory budget once per session and maps it to conservative/balanced/aggressive, with a Balanced fallback. Manual override via the "Preload Budget" dropdown.
- **Extension API** (`core/preload_registry.lua`) — `mod:register_asset_preloader(owning_mod, definition)`, gated by the memory tier, pcall-isolated per registration.
- **Squad loadout preloading** (`preload/squad_loadouts.lua`) — first extension built on the registry, and the actual expansion beyond InstantHub: preloads every human squadmate's equipped weapon/cosmetic packages, not just the local player's. Gated at `balanced` tier.
- Squad loadout refresh now skips profiles already resolved for the current mission context. Darktide replaces the profile table on canonical equipment/loadout updates, so this removes redundant five-second dependency scans and repeated missing-item logs without missing normal profile changes.
- **Selected mission warmup** (`preload/mission_warmup.lua`) — starts from backend-confirmed mission votes for standard, Havoc, and Expedition selections, with an authoritative mechanism fallback for Quickplay. Balanced warms level/theme/item dependencies; aggressive also warms the global non-hub breed dependency set. References are released on rejection, cancellation, loading completion, tier drop, disable, and unload.
- Expanded selected-mission warmup with a pure source-backed manifest resolver for game-mode, HUD, mission-view, loading-background, mission-intro, circumstance/Havoc mutator, nested mutator-spawner, and mutator visual-override packages. A bounded category-barrier scheduler stops at official loading handoff, validates package names, isolates failed submissions, and exposes `mission_warmup_info()` diagnostics.
- Expedition warmup now opportunistically copies concrete generated current-section levels and the immediately prior section's delayed-despawn levels, including eligible themes and item dependencies, when the existing mechanism exposes them before handoff. It does not regenerate layouts or implement speculative section lookahead.
- Mission warmup provides package availability only; it does not use resident loading or guarantee physical RAM/VRAM residency. The expanded Balanced scheduler was exercised in-game on fixed mission `fm_armoury`: 546 manifest packages loaded within the four-per-frame/eight-in-flight bounds, official-loading handoff stopped further submissions, and all 546 Instantium references were released after gameplay began. Quickplay, Havoc, Expedition, and Aggressive remain untested for this expansion.
- Added default-on bounded runtime texture/mesh warmup for approaching remote squad members, monsters, captains, specials, and elites. It uses Darktide's native unit force-stream requests with a 32-unit queue, one submission per frame, two units in flight, generation-safe callbacks, cleanup cooldown, a package-loading gate, a fail-closed 90% VRAM-pressure gate, and a session circuit breaker. Runtime-driven fixes replaced stale `POSITION_LOOKUP` values with fresh `Unit.world_position` calls and made candidate selection robust to `swap_delete`. Psykanium and a regular client mission completed without Instantium errors, texture timeouts, native failures, or circuit-breaker trips. Mesh requests timed out frequently, so visual/frame-time benefit remains unproven pending paired A/B testing.
- Removed external PowerShell/WMIC memory probes that could fail startup or flash console windows.
- Before this manifest expansion, the smaller mission warmup was smoke-tested in-game for fixed and Quickplay missions, Expedition, tier scope, and cleanup; hub/Psykhanium, squad loadouts, tier changes, disable/re-enable, and shutdown were also tested. Those results do not validate the expanded scheduler.
